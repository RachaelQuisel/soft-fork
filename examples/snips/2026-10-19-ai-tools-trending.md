### Snip 2: Claude Code can edit a TikTok. Teaching it funny is the hard part
- Source: How I AI with Claire Vo
- Episode/article: "Claude Code Can Edit a TikTok. Teaching It's Funny Is the Hard Part."
- Date: 2026-10-19 (listing also shown October 18 in another listing)
- Link: https://www.chatprd.ai/how-i-ai
- Summary: Brooke Lacey shows Claire Vo how Claude Code orchestrates FFmpeg, Whisper, and Python to turn phone footage into captioned shorts. The mechanics work: the tools cut, transcribe, and assemble the edit. The real work, in Brooke's telling, is encoding her timing, taste, and style, the judgment about what lands and what to cut. ### Snip 5: Claude Mem: stop re-explaining your project every session
- Source: MediaWeb Global
- Episode/article: "Claude Code in Practice: Plugins, Tips and Tricks for a Faster Workflow"
- Date: 2026-10 (checked October 2026)
- Link: https://www.mediaweb.global/blog/ai/claude-code-in-practice-plugins-tips-and-tricks-for-a-faster-workflow
- Summary: This practice guide describes the claude-mem plugin, which hooks the session lifecycle in Claude Code. It captures files touched and decisions made, compresses them to summaries locally, and injects the relevant pieces at the start of the next session. The problem it fixes is plain: re-explaining the project every session. The guide pairs it with Context7 for current documentation, so memory covers your project and the lookup covers the outside facts.
- Loop/workflow angle: memory as a loop step. Capture, compress, and re-inject is a small workflow on its own, and it is what lets every other loop start from where the last one stopped.

### Snip 9: From demos to production: six concepts that decide if an agent survives
- Source: DEV Community
- Episode/article: "From AI Agent Demos to Production: 6 Essential Concepts for Agentic AI System Design"
- Date: 2026-10-19
- Link: http://dev.to/lum_18/from-ai-agent-demos-to-production-6-essential-concepts-for-agentic-ai-system-design-2kki
- Summary: This October 19 design guide names six concepts: the agent loop, model routing, tool design, memory and state, orchestration choice, and evals with observability and security. Its math is the warning: at 90 percent success per step, three steps land at 72.9 percent and eight steps at 43 percent. Tool design is treated like API design, with idempotency, meaning a repeated call does not do the job twice, and memory, state, and RAG are kept separate. The closing rule is to build the simplest agent that reliably solves the problem.
- Loop/workflow angle: a design checklist for every loop in this file. Step count is a cost, routing is a saving, and a loop without evals and observability is a demo, however good it looks on the day.
